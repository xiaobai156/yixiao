## 正式提交与运行语义

- `single --formal` 是全量快照：必须提供本次预期站点集合，结果逐站且恰好覆盖该集合。空结果、缺站、多站、重复站、配置不一致和未签发成功结果均在写文件前拒绝。
- `retry --formal` 是显式授权的定点合并：仅对失败清单唯一匹配的站点使用正式模式抓取，不调用全量覆盖接口。清单空匹配或歧义返回 2，且不写文件。
- 不带 `--formal` 的 retry、repair、onboard 仍只读。workers 和 timeout 不再被静默忽略。
- 定点失败表示这一次未取得新证明，保留该站此前的成功 TXT 和缓存，只更新失败诊断；定点成功只合并选中站点，清除其失败行。同期不同旧值仍拒绝静默覆盖。
- 全量缓存门槛仍严格大于 85%；TXT 先写，缓存独立尝试。定点成功缓存不套用全量成功率门槛，失败复抓不撤销缓存。旧期回填仍需单独授权。
- 缓存批量预检后只调用一次批量更新，保留原有合法性、来源证据、隔离与同期冲突检查。定点模式不会顺带隔离或改写未选中坏缓存，遇到坏缓存则保留缓存并报告。
- 三列表格排行榜恢复为“内容、次数、排名”，相同次数并列且名次连续。未选中明细、相对顺序、分类分隔及附属内容保留。

## 准确性与取源修复

- 共识取源中任一次目标期或下一期的明确冲突会否决成功，不会被两次同值确认掩盖。下一期存在性检查与最终首尾方向检查分离，仍限定已证明的当前记录周期。
- 首页只有较新期数时继续读取同栏目连续下一页；全为更旧期数时停止；分页上限在额外网络请求前检查，不能跳页后声称完整。
- 锚点与作者区块先确定真实结束位置，再提取窗口与签发范围证据；窗口不得跨停止行或下一栏目。
- 来源与候选记录 ID 绑定，候选完整原始文本不得越过声明范围；过滤后空候选集合返回明确边界失败。
- 浏览器 JSON 按已知容器及当前文章/主题/用户身份投影，不因任意嵌套 ID 出现就放行整个响应；不同记录不得借用身份，重复目标记录内容冲突拒绝。
- API 全部 404 后先试页面 HTTP，只有确认为空壳才按配置使用浏览器。正文存在但缺目标字段时不通过浏览器碰运气。
- 移除证书错误后的不安全 TLS 降级，默认请求必须验证证书。证书有问题的站点将明确失败，需修复服务端证书或配置可信 CA，不能用关闭验证冒充正式成功。
- 来源身份比较改为同类型的所有已声明 ID 一致；未强制将同 URL 的不同栏目判成重复。配置加载处的栏目去重接入未推送，见下方限制。
- 验证回执补充 api_url，防止更换接口后沿用旧回执。

## 浏览器和文件写入

- 浏览器由最多两个专用线程持有并复用；每次抓取使用新的隔离上下文，不跨线程传递同步 Playwright 对象。退出时在持有线程清理。
- 图片、字体、音视频被拦截，脚本和正文请求保留。响应数量、单响应和累计字节设上限，声明的 Content-Length 在读正文前检查；未完成或失败的目标响应不得标记扫描完整。
- Playwright/浏览器底层仍可能缓冲未知长度或压缩响应；这些应用层限制不是浏览器进程内存的硬上限。
- 正式 TXT/缓存文件锁覆盖整个读取、合并、写回阶段，跨进程冲突立即拒绝，不在锁内做网络抓取。单文件原子替换与多文件备份日志配合，异常只回滚实际触及的文件。配置追加写入的跨进程锁未推送。
- 出现 `.zodiac-v2-*-output-transaction.json` 残留时拒绝新的同批正式输出。先按日志路径核对备份、新旧 SHA-256 与文件内容，再由维护者恢复；不要直接删除标记后重跑。
- 多文件替换不等于对未加锁读取者同时可见；Windows 目录 fsync 不可用，不能宣称任意断电下完全原子。
- `.gitignore` 仅阻止新增运行产物；不会自动删除此前已跟踪的缓存和诊断文件。
